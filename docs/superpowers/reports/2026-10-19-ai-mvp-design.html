1한눈에

MVP 로 AI 가 할 수 있는 것

  • 읽기 — 내 스터디 목록, 진행목표 트리(회차·묶음·과제·멤버·제약·version), 내 과제·개인 목표.
  • 진행목표 대량 작성·수정 — 회차·묶음·과제 추가, 일정 이동(shiftDescendants), 지정 담당. 선언형 계획서 하나로.
  • 항상 미리보기 먼저 — dry-run 이 기본, 적용엔 planHash 필수, 한 트랜잭션 원자 적용(부분 적용 없음).
  • 개인 목표 일괄 추가 — 한 회차에 1~20개 원자 추가.
  • 할 수 없는 것 — 보관·삭제, 제출 작성, 멤버 승인, 방 삭제. 서버는 LLM 을 부르지 않음.

예시 흐름 — Claude Code 에서 "AWS 스터디 8주 진행목표 짜줘"

  1. 사용자 → Claude Code"AWS 스터디 8주 진행목표 짜줘"
  2. Claude → get_curriculum(slug)현재 트리 + 방 기간·오늘(KST)·멤버·제약·version V 수신
  3. Claude (클라이언트 측)sgtudy.plan/v1 계획서 초안 작성, baseVersion: V 포함
  4. Claude → apply_curriculum_plan(dryRun: true){ ok, planHash H, diff, warnings, errors, notifications 미리보기 } — DB 에는 아무것도 남지 않음
  5. Claude → 사용자diff·경고·알림 미리보기를 보여 주고 명시적 승인 요청(도구 설명이 요구)
  6. Claude → apply_curriculum_plan(dryRun: false, planHash: H, idempotencyKey: K){ ok, refs{ref→id}, diff, version V' } — 팀원 알림은 수신자당 최대 1건

MVP 완료 기준(스펙 §10): claude mcp add --transport http sgtudy https://<도메인>/api/mcp --header "Authorization: Bearer sgt_pat_…" → "aws 에 5주차 추가" 가 dry-run diff → 승인 → 적용, 팀원 알림 ≤ 1건.

3인증·권한

PAT (1단계)

  • 형식 sgt_pat_ + 64 hex (uuid 2개, ≈244bit)
  • DB 에는 sha256 hex 만. 원문은 생성 응답에서 1회
  • 목록 표시는 접두 16자(sgt_pat_+8 hex)
  • 스코프 3개: read curriculum:write personal:write (기본 모두 체크, 해제 가능)
  • 만료 30/90/365일, 기본 90일, 만료 필수
  • 사용자당 활성 토큰 10개
  • PAT 로 PAT 생성 불가(API_FORBIDDEN) — 브라우저 세션 전용

토큰 관리 UI — /me 「AI 연결」

  • 이름 · 스코프 체크박스 · 만료 select → [토큰 만들기]
  • 생성 직후 원문 + [복사] + claude mcp add 명령 예시, "이 화면을 떠나면 다시 볼 수 없어요"
  • 목록: 이름 · 접두 · 스코프 · 마지막 사용 · 만료일(만료됨 배지)
  • [폐기] — 확인 대화상자, 즉시 반영

PAT → 사용자 신원: DB 게이트웨이

  • current_user_id() 를 coalesce(auth.uid(), nullif(current_setting('sgtudy.api_uid', true), '')::uuid) 로 재정의 → 모든 기존 RPC 가 무수정으로 토큰 주인 권한으로 동작.
  • sgtudy.api_uid 를 set_config(…, true)(트랜잭션 한정) 하는 함수는 api_authenticate 하나뿐 — 정적 회귀 테스트로 고정. PostgREST 클라이언트는 request.* 외 GUC 설정 불가.
  • auth.uid() 가 있으면 GUC 무시(coalesce 순서). 로그인 세션 + 토큰 동시 → API_AUTH_CONFLICT.

장치동작
dry-run 충실도실제 RPC(node_create_core·node_update·node_move)를 plpgsql 서브트랜잭션에서 끝까지 실행 → diff·알림 미리보기를 변수에 담고 일부러 예외로 되감음. 미리보기와 적용의 검증·결과가 같다. dry-run 의 diff[].id 는 null
planHashmd5(plan::jsonb::text || version), 상태 저장 없음. 적용 시 불일치 → PLAN_NOT_PREVIEWED (기대값은 알려 주지 않음)
baseVersion 동시성다르면 STALE_VERSION(hint: current). 없으면 동시 수정이 해시 불일치로만 보이므로 도구 설명이 항상 넣으라고 안내. curriculum_version 은 팀 노드 구조·일정·제목·설명·유형·보관·지정 배정의 md5 — 제출·개인 목표는 제외
원자성적용은 한 트랜잭션, 첫 오류에서 전체 롤백, errors[0].path 로 위치. 정적 검증은 실행 전에 모든 오류를 모아 반환
멱등성idempotencyKey ≤ 64자. 같은 사용자·키·요청 해시 → 저장 응답 재반환(replayed:true), 해시 다르면 IDEMPOTENCY_CONFLICT. 24시간 보관. 버전 검사보다 먼저 판정
크기 상한256KB · 노드(중첩 포함) ≤ 200 · 무거운 op(update·move·담당 지정 create, 각각 curriculum_json 1회) ≤ 50 · 깊이 ≤ 5 · 제목 80 · 라벨 20 · 설명 20,000

알림 묶기 — 계획 1건 = 수신자당 최대 1건

  • 이 트랜잭션에서 생긴 SCHEDULE_CHANGED·ROUND_SCHEDULE_CHANGED·TASK_ASSIGNED·TASK_UNASSIGNED(행위자 = 나, 이 방, 시작 전 max(id) 이후)를 수신자별로 셈.
  • 1건 → 원래 알림 그대로(문구·딥링크 유지). 2건 이상 → 지우고 CURRICULUM_BULK_UPDATED 1건.
  • 제목 {방} 진행목표가 한꺼번에 바뀌었어요, 본문 일정 n건 · 담당 m건(0 항목 생략), 링크 /my-study/{slug}?tab=curriculum.
  • 새 과제 생성은 원래 알림 없음. 이 계획 밖 알림은 건드리지 않음. dry-run 응답에 perRecipient:[{nickname, count, collapsed}] 미리보기.

11검토 요청 — go 전에 확인할 것

  • 범위 — MVP 도구 5개와 create/update/move 만(보관·삭제 없음)으로 충분한지.
  • 인증 순서 — 1단계는 Claude Code 전용(PAT), claude.ai/Desktop 은 OAuth 가 붙는 2단계까지 못 쓰는 것 수용 여부.
  • 노드 상한 — 호스티드 PostgREST 가 함수 timeout 을 반영하지 않으면 계획 1건 노드 상한이 200 → 100 으로 줄어드는 것 수용 여부.
  • 인증 실패 무제한 — 실패한 토큰 시도가 레이트리밋·감사에 안 잡히는 것을 MVP 에서 수용할지, 별도 처리할지.
  • 표 성장 — api_audit·api_idempotency 행 삭제가 2단계 cron 까지 없는 것 수용 여부.
  • 라우트 검증 수준 — Route Handler 는 스모크만, 실 연결 확인은 배포 후 마스터 계정으로 사용자가 직접(dry-run 확인, 적용은 테스트 방) — 이 방식이 괜찮은지.
  • 배포 작업 — supabase db push(0030–0032)와 Vercel MCP_ALLOWED_ORIGINS 설정은 사용자가 승인 후 직접 실행(service role 불필요).
  • 마이그레이션 번호 — 0030~0032 가 다른 작업과 겹치지 않는지(겹치면 Task 0 에서 멈춤).
