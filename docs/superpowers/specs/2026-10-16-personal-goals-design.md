## 0. 사용자 요청 (원문)

> "한 주차에서 각 팀원들은 자신만의 과제/소단위 목표 각자 등록이 필요한데 그래야 내가 맡아야 할 항목만 보고 싶을 때 내 과제 페이지에서 볼 수 있을 거야. 지금 이 기능은 없는데 추가를 위해 화면 전반 ui/ux 고려하고 시나리오 작성 및 설계 진행"

요구 해석:
1. 팀원 누구나(진행목표 편집 권한 없이) 회차 아래에 **자기만의 과제/소단위 목표**를 등록한다.
2. **"내 과제" 페이지**에서 내가 맡은 것만 — 배정된 팀 과제 + 내 개인 목표 — 모아 본다.
3. 앱 전체 화면(진행목표 목록·보드·간트·캘린더·개요·내 일정·헤더)에서 일관되게 보인다.

| 팀 진척률(전체·회차·묶음, `room_progress`) | **제외** | 배정 행이 없어 자동 제외. 팀원이 목표를 많이/적게 만든다고 팀 수치가 흔들리면 안 된다 |
| 방 통계·현재 회차 과제·내 진척·다음 마감(`room_leaf_stats`) | **제외** | `task_type in ('COMMON','DESIGNATED')` 로 한 줄 수정 |
| 메인 카드 "내 진척"(`rooms_list`) | 제외(자동) | 배정 기반 |
| 개인 진척 | **별도** — 내 과제 머리 "개인 목표 x/y 완료", 개요 내 카드, 그룹장 멤버 표 열 | 프론트 계산(커리큘럼·`me_tasks` 데이터) |
| 노드 자체 값(`assigned/submitted/state`) | 개인 = 1/0·1 (보관이면 0/0) | 상세·행 상태 표시용. 부모로 합산하지 않는다(서버 롤업은 배정 기반이라 0, 프론트 `buildTree` 도 롤업에서 뺀다) |

### 5.4 권한 표

| 동작 | 소유자(그룹장 또는 ACTIVE 멤버) | 그룹장(남의 것) | 위임 편집자(남의 것) | 다른 ACTIVE·INACTIVE 멤버 | 대기자·외부·비로그인 |
|---|---|---|---|---|---|
| 보기(목록·상세·제출물) | ✓ | ✓(보관 포함) | ✓ | ✓(보관 제외 — 프론트) | ✗ (RLS·RPC 에서 안 내려옴) |
| 만들기 | ✓ (방 RECRUIT·ACTIVE, 회차 보관 아님, 회차당 20개) | — | — | — | ✗ |
| 고치기(제목·설명·기간·회차 이동) | ✓ | ✗ | ✗ | ✗ | ✗ |
| 완료 표시/취소 | ✓ (방 ACTIVE) | ✗ | ✗ | ✗ | ✗ |
| 제출(메모·링크·파일) | ✓ (제출 설계 그대로) | ✗ | ✗ | ✗ | ✗ |
| 보관/해제 | ✓ | ✓ (해제는 소유자가 자격 있을 때만) | ✗ | ✗ | ✗ |
| 삭제 | ✓ (제출째 삭제) | ✓ 제출 없을 때만 | ✗ | ✗ | ✗ |
| `node_*`(편집자 RPC)로 손대기 | ✗ `PERSONAL_NODE` | ✗ | ✗ | — | — |
| 회차 삭제·보관으로 함께 처리 | 회차 서브트리 규칙대로(제출 있으면 삭제 거부) | | | | |

- 이탈(INACTIVE)·취소(CANCELED)로 자격을 잃으면 `assignment_resync` 가 그 사람의 개인 목표를 **자동 보관**한다(제출물 보존). 다시 ACTIVE 가 되면 본인이 보관 해제.
- 방 상태: 만들기·고치기·보관·삭제 = RECRUIT·ACTIVE(미보관). 완료 = ACTIVE 만(제출과 같은 규칙, 대신 시작일 검사 없음 — 개인 목표는 미리 끝내도 된다). DRAFT 는 그룹장 혼자라 개인 목표가 필요 없고, `room_open_recruit` 의 "말단 과제 1개 이상"(`0004:423`) 판정을 개인 목표가 통과시키지 않게 막는다.
- 기간: 방 기간 **안**만(밖이면 `INVALID_PERIOD` reason room) — 팀원이 그룹장의 방 종료일 조정(`0004:555-557`)을 막지 못하게. 회차 기간 밖은 경고만(`PERIOD_OUTSIDE_PARENT`, 팀과 같음).
- 한도: 소유자당 회차당 보관 제외 **20개**(`PERSONAL_LIMIT_EXCEEDED {limit:20}`), 제목 1~80자, 설명 20,000자(팀과 같음).

### 5.5 RPC (0014)

| RPC | 시그니처 | 반환 | 요점 |
|---|---|---|---|
| `personal_create` | `(p_slug, p_round_id bigint, p_title text, p_start_date date = null, p_end_date date = null, p_description_md text = '')` | Curriculum + `createdId` + `warnings` | 기본 기간 = 회차 기간(방 기간으로 자름), 회차 끝 순서 |
| `personal_update` | `(p_slug, p_node_id bigint, p_patch jsonb)` 키 `title·descriptionMd·startDate·endDate·roundId` | Curriculum + `warnings` | 회차 이동 + 기간을 한 트랜잭션에(팀 이동의 2회 호출 문제 없음) |

| `personal_delete` | `(p_slug, p_node_id)` | Curriculum | 소유자 = 제출·링크까지 삭제(첨부 soft delete). 그룹장 = 제출 없을 때만 |
| `personal_complete` | `(p_slug, p_node_id, p_done boolean)` | Curriculum | 완료 = 빈 제출 행(지각 판정 `kst_deadline`). 취소 = 본문·링크·첨부가 없는 제출만 삭제, 있으면 `SUBMISSION_HAS_CONTENT` |
| `me_tasks` | `()` | MeTasks (§5.6) | 내 과제 페이지 |

재정의(최신 정의 복사 + 추가분): `node_get`(PERSONAL 거부) · `is_task_assignee`(소유자 포함) · `goal_nodes_select` 정책(남의 개인 목표는 그룹장·ACTIVE·INACTIVE 멤버만) · `curriculum_json`(노출 필터, `ownerId`, 개인 `task`, stats 팀만, `personal: {canAdd, perRound}`) · `room_leaf_stats`(팀만) · `task_node_json`(개인 people·집계) · `task_get`(노출 필터) · `tag_autoselect`(개인 제목 제외) · `assignment_resync`(자격 잃은 소유자의 개인 목표 보관) · `me_schedule_leaves`(시그니처 변경 → drop/create, 개인 포함·남의 개인 제외) · `me_schedule`(`tasks[].personal`).

오류 코드(새): `PERSONAL_NODE`, `NOT_OWNER`, `NOT_ACTIVE_MEMBER`, `OWNER_NOT_ACTIVE`, `PERSONAL_LIMIT_EXCEEDED`, `SUBMISSION_HAS_CONTENT`. 기존 재사용: `ROOM_NOT_FOUND`, `ROOM_NOT_EDITABLE`, `ROOM_NOT_ACTIVE`, `NODE_NOT_FOUND`, `PARENT_ARCHIVED`, `TASK_ARCHIVED`, `INVALID_TITLE`, `INVALID_PERIOD`, `NODE_HAS_SUBMISSIONS`, `VALIDATION_FAILED`.

### 5.6 DTO 변화

```ts
type TaskTypeDto = "common" | "designated" | "personal";
type NodeDto = { …; ownerId?: string | null };                  // 개인 목표만 값
type Curriculum = { …; personal?: { canAdd: boolean; perRound: number } };   // myPermissions 는 그대로(기존 테스트가 객체 전체를 비교)
type ScheduleTask = { …; personal?: boolean };
type MeTasks = {
  today: string; personalPerRound: number;
  studies: { slug; title; tone: Tone; status: RoomStatusDto; membership: "leader" | "joined"; currentRoundId: string | null; canAddPersonal: boolean }[];
  rounds: { id; slug; label: string | null; title; startDate; endDate; canAdd: boolean }[];      // 보관 아닌 루트
  items: { id; slug; roundId; groupTitle: string | null; title; type: TaskTypeDto; startDate; endDate;
           st: TaskStatus; submittedAt: string | null }[];       // 내 유효 배정 팀 리프 + 내 개인 목표(보관 제외)
};
```

`me_tasks` 대상 방 = 내가 그룹장이거나 ACTIVE 멤버, 보관 아님(DRAFT 는 그룹장만). `canAddPersonal` = 방 RECRUIT·ACTIVE.

## 7. 엣지 케이스

| 경우 | 기대 동작 |
|---|---|
| 회차 기간 변경 | 개인 목표 기간 불변. 소유자 상세·폼에 회차 밖 경고 |
| 방 기간 축소로 개인 목표가 방 밖 | 방 진행 중에는 종료일을 마지막 노드 마감 뒤로만 줄일 수 있다(`0004:555-557`, 개인 포함) — 개인 목표는 방 안에서만 만들어지므로 새로 막는 일은 없다. DRAFT/RECRUIT 에서 줄이면 PERIOD_OUTSIDE_ROOM 경고(기존). 이후 개인 목표 수정 시 방 안으로 맞추라는 오류 |
| 회차 삭제(개인 목표 제출 없음) | 함께 삭제. 확인 문구에 개수. 알림 없음 |
| 회차 삭제(개인 목표 제출 있음) | `NODE_HAS_SUBMISSIONS` → 보관 제안(기존 `removePlan` — subAll 에 개인 제출 포함) |
| 회차 보관 → 해제 | 함께 보관·해제. 해제 직후 resync 가 이탈자 것만 다시 보관 |
| 팀 과제를 회차 사이로 이동·순서 변경 | 개인 목표 영향 없음. 서버 형제 index 는 개인 목표도 센다 → 프론트 index 계산은 서버 순서 kids 기준(`dropPlan`·`reorderIndex` — Review Focus) |
| 회차 안에 개인 목표만 있음 | 회차 pct = 0%(팀 과제 없음, 기존 빈 회차와 같음). 회차 상세 "이 회차의 과제 0개 · 아직 과제가 없어요" + 내 개인 목표 섹션 |
| 이탈·취소 | 자동 보관. 재참가해 ACTIVE 면 본인이 해제(한도·회차 보관 검사) |
| 그룹장 위임 해제 | 무관(개인 목표 권한은 위임과 별개) |
| `leader_does_tasks = false` 인 그룹장 | 팀 과제 배정은 없지만 개인 목표는 만들 수 있다. 내 과제에 개인 목표만 |
| 승인 대기자(PENDING) | 개인 목표 못 만들고 남의 것 못 봄. 내 일정 미리보기에서도 남의 개인 목표 제외(`me_schedule_leaves` 수정) |
| 공개 방 비로그인 | 진행목표에 개인 목표 없음(RLS·`curriculum_json`·`task_get` 3중) |
| 다른 사람 개인 목표 id 로 `task_get` (비멤버) | `NODE_NOT_FOUND` (존재 숨김) |
| 편집자가 `node_update`/`node_move`/`node_delete` 로 개인 목표 지정 | `PERSONAL_NODE` |
| 편집자가 팀 과제를 개인 목표 "아래" 로 드래그 | 프론트는 개인 행을 편집 모드에 그리지 않음 + 서버 `node_get`(부모) 가드 + 트리거 |
| 빠른 추가 연타 / IME | 기존 `shouldSubmitQuickAdd`·busy 규칙. 개인 추가는 낙관적 임시 행 없이 응답 대기(입력 `aria-busy`, 응답 후 행 등장) — 서버 한도·기간 오류를 바로 보여 주기 위해 |
| 완료 체크 연타 | busy 동안 버튼 비활성, 응답 값으로만 갱신 |
| 제출 카드로 메모를 남긴 개인 목표의 완료 취소 | `SUBMISSION_HAS_CONTENT` → 토스트 + 체크 그대로 |
| 시작 전 개인 목표 완료 | 허용(진행 중 방). 상태 "기한내 완료" |
| 마감 지난 개인 목표 완료 | "늦게 완료"(is_late) |
| 방이 ACTIVE 아닐 때 체크 | 버튼 비활성 + title "스터디가 진행 중일 때 완료할 수 있어요" |
| 종료된 방 | 내 과제 "전체" 에서 읽기 전용. 체크·추가 숨김 |
| 보관된 방 | 내 과제·내 일정에서 빠짐(기존 규칙) |
| 한 회차 20개 도달 | 추가 줄 대신 한도 안내. 서버도 거부 |
| 두 탭 동시 수정 | 마지막 저장이 이김(팀 과제와 같음) |
| 알림 `?task=` 로 개인 목표 | 개인 목표용 알림은 없지만 링크 규칙은 같아 상세가 열린다 |
| 계정 삭제(프로필) | 범위 밖(FK NO ACTION — 팀 배정과 같은 처리 필요 시 후속) |

| R8 | 개인 목표 관련 새 알림 없음(마감 알림 포함). 필요하면 후속 |
| R9 | 한도 회차당 20개, 기간은 방 기간 안 |
| R10 | 개인 → 팀 과제 승격, 개인 목표 순서 바꾸기, 개인 목표 하위 단계, 공개 범위 선택은 v1 범위 밖 |

## 9. 통합 지점 — 과제 상세·제출 (`2026-10-16-task-submission-design.md`)

- 제출 설계 §7 은 "개인 과제 = task_type 리프 + 소유자 배정 행" 을 요청했다. 이 설계는 **배정 행 대신 `is_task_assignee` 확장**으로 같은 결과를 낸다(R1 — 이유 §5.1 P2). 제출 카드·업로드(`is_my_task`)·`task_get.isAssignee`·`submission_target` 은 수정 없이 소유자를 담당자로 본다. `task_node_json` 이 개인 목표의 `people = [소유자+상태]`, `assigned 1`, `submitted 0|1` 을 주므로 "제출 현황 1/1" 이 그대로 그려진다.
- `submission_upsert` 의 `TASK_ALL_SUBMITTED` 는 `room_leaf_stats` 를 보는데 0014 에서 개인을 빼므로 개인 목표 제출은 그룹장 알림을 만들지 않는다(의도).
- 0015(`file_discard`)는 0014 가 재정의하는 함수(`task_get`·`task_node_json`·`is_task_assignee`)를 건드리지 않는다고 제출 설계가 밝혔다(§7 마지막 줄). 만약 0015 가 이 함수들을 다시 정의하게 되면 **0014 판을 복사해** 고쳐야 한다(개인 노출 필터 유실 방지).
- 내 과제 → 상세 = `/my-study/{slug}?task={id}` (제출 설계 §2.6 포커스 규칙). 상태 배지 값은 같은 `task_code`.
- 개인 목표 상세에서 "완료로 표시"(빈 제출)와 제출 카드의 "제출하기"(내용 있는 제출)는 같은 행을 만든다. 카드는 빈 제출을 막지만(제출 R5) 체크로 만든 빈 완료가 있으면 카드는 "제출됨(내용 없음) · [수정하기]" 로 보이고 내용을 덧붙일 수 있다 — 제출 설계 쪽에 "본문·링크·파일이 모두 비어 있는 제출" 표시 한 줄을 요청한다.

## 10. 수용 기준

1. ACTIVE 멤버(편집 권한 없음)가 진행목표 보기 모드에서 펼친 회차의 "＋ 내 목표 추가" 로 제목만 쳐서 Enter 하면 [개인] 행이 그 회차의 팀 과제 아래에 생기고 기간 = 회차 기간이다. 입력은 다음 목표를 위해 열려 있다.
2. 개인 목표를 만들어도 전체 진척률·회차 pct·"과제 N개"·개요 팀 수치·메인 카드 내 진척이 바뀌지 않는다.
3. 다른 멤버 목록에는 기본으로 남의 개인 목표가 안 보이고 "팀원 목표" 칩을 켜면 보인다. 비로그인·대기자·외부에는 어떤 경로(curriculum_get·task_get·표 직접 조회)로도 안 보인다.
4. 소유자만 제목·설명·기간·회차를 고칠 수 있고, 회차를 바꾸면 기간 미리보기대로 한 번에 옮겨진다. 그룹장은 남의 개인 목표를 보관/삭제(제출 없을 때)만 할 수 있다. 위임 편집자는 손댈 수 없다(`PERSONAL_NODE`/`NOT_OWNER`).
5. 진행 중 방에서 개인 목표 체크 버튼으로 완료·완료 취소가 되고 상태(기한내/늦게)가 내 과제·진행목표·보드·캘린더·간트·내 일정에 같은 값으로 보인다. 내용이 있는 제출은 취소되지 않는다.
6. 헤더에 "내 과제" 가 세 번째 메뉴(내 스터디와 내 일정 사이)로 있고, 내 배정 팀 과제 + 내 개인 목표를 방·회차별로 보여 준다. "이번 회차/전체", "회차/마감일", 유형, 완료 숨기기, 스터디 필터가 동작하고 URL 로 유지된다. 행을 누르면 그 과제 상세(제출 영역 포커스)가 열린다.
7. 내 과제 회차 묶음 끝·머리 버튼으로 개인 목표를 추가할 수 있고, 종료된 방·한도 도달 회차에는 추가 UI 가 없다.
8. 이탈 처리된 멤버의 개인 목표는 자동 보관되고 팀 수치에 영향이 없다. 회차 삭제 확인에 개인 목표 수가 나온다.
9. 편집 모드 목록·드래그·위/아래 순서가 개인 목표가 섞인 회차에서도 의도한 자리로 옮긴다.
10. 390/820/1440 가로 스크롤 없음, 안쪽 세로 스크롤러 없음, 새 누르는 자리 ≥ 44px, 상태는 색 + 모양.
11. `npm run test:db`(0014 테스트 포함) · `npm run lint && npx tsc --noEmit && npx vitest run` 통과. 0014 는 호스티드 기존 행을 바꾸지 않는다(추가형).
