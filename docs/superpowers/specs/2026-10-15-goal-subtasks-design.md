### 1.3 사용자가 "+를 누르면 회차 정보만 기입 가능" 하다고 느낀 이유 (근본 원인)

1. **가장 눈에 띄는 "+" 는 "회차 추가"** 다. 누르면 회차 편집 화면이 열리는데, 이 화면에는 하위 과제를 넣는 자리가 없다(`EditView.tsx:210-216` 은 숫자 글자뿐). 회차 화면 = 회차 정보만 쓰는 곳.
2. 행 "+" 는 오른쪽 끝의 작은 아이콘이고 라벨이 없다(툴팁만). 눌러도 **목록이 사라지고 바로 과제 편집 화면**이 열려, 새 과제가 회차 안에 들어간 모습을 보지 못한다. 편집 화면 머리는 회차 편집 화면과 모양이 같아(제목·기간·설명) "회차 정보를 또 쓰는" 것처럼 보인다. 과제임을 알리는 것은 작은 회색 경로 글자와 유형 선택뿐.
3. 회차가 무엇인지(일정·대주제 컨테이너)와 과제가 무엇인지(실제 할 일) 화면 어디에도 구분해 말하지 않는다. "하위 항목", "묶음" 같은 트리 용어가 섞여 있다.
4. 보기 모드에서는 회차 내용을 볼 수 없어, 회차에 무엇을 써 둘지 동기가 없다.

### 2.1 백로그('미배정' 바구니)를 넣지 않는 이유

- DB 규칙상 회차 아닌 노드는 반드시 회차(round_id) 아래에 있다(`0006:28-41`). 백로그를 넣으려면 ① 가짜 루트 회차(라벨 "N주차" 번호·개요의 회차 창·ROUND_STARTED 알림·진척률·간트에 다 섞인다) 또는 ② parent 없는 과제를 허용하는 스키마 변경(트리거·롤업·curriculum_json·알림 전부 수정)이 필요하다. 둘 다 호스티드 데이터에 위험하고 이득이 작다.
- 스터디는 주 단위 계획이 기본이라 "언젠가 할 일" 이 드물다. 미룰 과제는 다음 회차로 **옮기면** 되고, 안 할 과제는 **보관**(기존)하면 참가자 화면에서 숨겨지고 제출물은 남는다.
- 필요가 확인되면 후속 마이그레이션(가칭 0013 backlog)으로 따로 설계한다. 이번 범위 아님.

### 2.2 트리 단순화 (2단계) — 판정

- **UI 는 회차 → 과제 2단계만 만든다.** "+" 는 회차 행에만, 과제 행에는 없다(지금도 없음). 묶음을 새로 만드는 UI 없음.
- **DB 는 바꾸지 않는다(마이그레이션 없음).** depth 4~5 를 막는 제약을 추가하면 기존 묶음 데이터가 있는 호스티드 방에서 위반이 난다. 추가형(additive)·무손실 원칙.
- 기존 묶음(회차 아래 부모 노드)은 지금처럼 목록·간트에 보이고, 편집 화면에서 "묶음" 으로 표시. 묶음 안 과제는 "회차" 선택으로 회차 바로 아래로 옮길 수 있다(= 자연스러운 평탄화). 묶음 자체도 삭제·보관·이동 가능. 묶음 행의 "+" 는 없앤다(새 3단계 생성 금지).
- 호스티드에 묶음이 얼마나 있는지는 실행 전에 읽기 전용으로 확인한다: `select count(*) from goal_nodes where depth > 3;` (플랜 Task 0, 사용자 실행). 0 이면 나중에 2단계 제약 마이그레이션을 검토할 수 있다 — 이번 범위 아님.
- 리프 회차(A7)는 UI 가 만들지 않는다. 회차 선택 목록은 회차만, 루트로 옮기는 동작은 없다.

### 3.2 목록 (진행목표 탭, 한 페이지 스크롤 유지)

**보기 모드**
- 회차 행: 왼쪽 꺾쇠 = 접기/펼치기(지금 그대로). **행 본문(제목 영역) 클릭 = 회차 상세 화면 열기**(3.4).
- 과제 행: 본문 클릭 = **과제 상세 화면**(3.4). 인라인 `LeafDetail` 펼침은 없앤다(상세 화면이 대체 — 회차·과제가 같은 방식으로 열리고 URL·뒤로 가기가 된다).
- 묶음 행: 꺾쇠 = 접기, 본문 = 묶음 상세(회차 상세와 같은 화면, 라벨 배지 없음).

**편집 모드**
- 회차 행 "+" (44px, 오른쪽 J의 삭제 버튼 왼쪽): 그 회차를 펼치고 그 회차 끝의 빠른 추가 입력을 열어 포커스. **편집 화면으로 넘어가지 않는다.**
- 펼쳐진 각 회차의 마지막 자식 아래에 "+ 과제 추가" 줄(높이 44px, 들여쓰기 = 과제 깊이). 누르면 같은 자리가 빠른 추가 입력으로 바뀐다.
- 빠른 추가: 제목 입력 → Enter = `node_create(회차, 제목)` → 새 과제 행이 회차 안 끝에 나타나고(낙관적 임시 행 → 서버 응답으로 교체), 입력은 비워진 채 열려 있어 다음 과제를 바로 쓴다. 빈 Enter = 아무 일 없음. Esc 또는 바깥 포커스 이동(빈 입력일 때) = 닫기. 80자 제한(`maxLength=80`, 서버 `INVALID_TITLE` 와 같음). IME 조합 중 Enter 무시(`e.nativeEvent.isComposing`). 실패 시 토스트 + 입력에 글자 되살림.
- 새 과제 기본값: 유형 **공통**(→ 활성 참가자 전원 자동 배정), 기간 = **회차 기간**, 순서 = 끝. 서버 `node_create` 기본값 그대로(변경 없음).
- 과제 행·묶음 행에는 "+" 없음(묶음 행의 기존 "+" 제거).
- 순서·회차 이동: 데스크톱(≥640)에서 드래그 핸들(지금은 장식, `TreeRow.tsx:39-45`)로 과제 행을 끌어 같은 회차 안 순서 변경 또는 다른 회차 위/안에 놓아 이동(3.5). 모바일·키보드는 회차 화면의 위/아래 버튼과 과제 화면의 회차 선택으로 같은 일을 한다.
- 회차 행 클릭 = 회차 편집 화면(지금 그대로), 과제 행 클릭 = 과제 편집 화면(그대로).
- "회차 추가" 는 지금처럼 새 회차 편집 화면을 연다(회차는 기간·대주제부터 정해야 하므로). 그 화면의 과제 섹션에서 바로 과제를 넣는다.

### 3.3 회차 편집 화면 (`EditView`, 회차·묶음일 때)

순서: 고정 막대(← 진행목표 · 경로 · 삭제 · 저장) → 제목 → 기간 한 줄 → **과제 섹션** → 설명(마크다운).

과제 섹션 "이 회차의 과제 N개" (`ChildList`, 편집형):
- 한 줄 = 유형 배지 · 제목 · 기간(MM.DD – MM.DD) · 담당자 아바타(≥640) · 제출/배정 `sub/asg` · 담당자 미정 배지 · 보관됨 배지. 줄 본문 클릭 = 그 과제 편집 화면(미저장 수정 확인 `request({sel})` 경유 — URL 은 replace).
- 줄 오른쪽: 위로 / 아래로(44px, 맨 위/맨 아래에서는 비활성) → `node_move(id, 같은 부모, index±1)`. 삭제(J 의 `removePlan` + `InlineConfirm` 재사용, 줄 안 확인).
- 섹션 끝: "+ 과제 추가" → 빠른 추가 입력(3.2 와 같은 컴포넌트).
- 섹션은 회차 화면을 저장하지 않아도 동작한다(구조 변경은 즉시 RPC — 지금 규칙과 같음). 단, 회차에 미저장 수정이 있어도 과제 추가·순서·삭제는 허용(회차 필드 오버라이드와 독립). 과제 열기는 기존 미저장 확인을 거친다.
- 묶음(기존 데이터) 화면도 같은 섹션을 보여 준다(추가 버튼 포함 — 묶음 안 과제 추가는 depth 를 늘리지 않으므로 허용).
- 진척률 문구 "하위 항목 N개 · 진척률 N%" 는 "과제 N개 · 진척률 N%" 로.
- 한 페이지 스크롤: 섹션은 내용만큼 자란다(안쪽 세로 스크롤 금지, h-report). 설명 편집기 min-height 는 회차일 때 `420px` 고정(과제 섹션이 위에 있어 `100dvh − 520px` 계산이 맞지 않음).

### 3.4 과제 편집 화면 (`EditView`, 리프)

  - 바꾸면 즉시 이동(구조 변경 = 즉시 RPC). 그 과제에 미저장 수정이 있으면 select 를 비활성화하고 문구 "저장한 뒤 옮길 수 있어요".
  - 고르기 전 미리보기: select 아래에 "옮기면 기간이 10.08 – 10.10 으로 바뀌어요" 또는 "기간은 그대로예요".
  - 새 회차 안 순서 = 끝.
- 임시 노드(`temp`)일 때 회차 선택·경로 링크 비활성.

### 3.5 이동 규칙 (회차 사이)

| 항목 | 규칙 |
|---|---|
| RPC | `node_move(slug, 과제id, 새회차id, index)` (index 생략 = 끝). 묶음 통째 이동도 같은 RPC(서브트리 depth 검사는 서버) |
| 기간 | **제출이 하나라도 있으면(subAll>0) 기간 유지** — 제출 기한·지각 판정을 소급해 바꾸지 않는다. 제출이 없고 과제 기간이 새 회차 기간 안이면 유지. 밖이면 **회차 시작 기준 오프셋·기간 길이를 유지해 옮기고 새 회차 끝을 넘으면 끝에 맞춘다**(시작 = 새 회차 시작 + (옛 시작 − 옛 회차 시작), 그 시작을 [새 시작, 새 끝]으로 클램프, 끝 = min(시작 + 길이, 새 끝)). 계산은 순수 함수 `movedPeriod` |
| 기간 저장 | `node_move` 성공 후 바뀐 기간이 있으면 `node_update(startDate,endDate)` 한 번 더. 두 번째가 실패하면 이동은 유지하고 토스트 "옮겼지만 기간은 바꾸지 못했어요 · {오류}" (마이그레이션 없이 가는 대가; 거의 일어나지 않음) |
| 담당자 | 그대로(`task_assignments` 는 node_id 기준). 공통은 `assignment_resync` 가 다시 맞춤 |
| 제출물 | 그대로(node_id 기준) |
| 진척률 | 서버 응답의 새 롤업 |
| 거부 | 보관된 과제·보관된 회차로는 불가(서버 `TASK_ARCHIVED`/`PARENT_ARCHIVED` — 선택 목록에서 보관 회차는 빼고, 보관된 과제는 select 비활성) |
| 같은 회차 안 순서 | `node_move(id, 같은 부모, 새 index)`, 기간 불변 |
| 낙관적 처리 | 없음(이동 중 줄 `aria-busy`, 버튼 비활성). 응답 Curriculum 으로 교체 — 서버가 순서·depth 를 재계산하므로 흉내 내지 않는다 |
| 알림 | 새 알림 없음(기간이 바뀌면 node_update 의 기존 SCHEDULE_CHANGED 규칙을 그대로 따른다) |

### 3.6 보기 모드 상세 화면 (`DetailView`, 새 컴포넌트) — 사용자 요청 2

**판정: 인라인 펼침이 아니라 목록 자리를 쓰는 읽기 전용 상세 화면.** 이유: ① 편집 화면과 같은 자리·같은 `?item=` URL 규칙이라 뒤로 가기·새로고침·링크 공유가 그대로 된다 ② 회차 설명(마크다운, 표 포함)은 길 수 있어 행 아래 펼침이 목록을 크게 밀어낸다 ③ 회차를 펼치면 이미 자식 행이 보이는데 인라인 회차 상세가 끼면 자식 목록이 두 번 보인다.

- URL: 보기 = `?tab=curriculum&item=<id>` (mode 없음), 편집 = `?tab=curriculum&mode=edit&item=<id>`. 열기 push, 항목→항목 replace, 닫기 back/replace — `urlStep` 그대로.
- 상태: `ScreenState.viewSel: string | null` (편집용 `editSel` 과 분리). 편집 모드로 바꾸면 `viewSel` 의 항목을 `editSel` 로 넘긴다(같은 항목의 편집 화면). 편집 모드에서 보기로 바꾸면 `editSel` → `viewSel`(미저장 확인 기존 그대로).
- 회차(·묶음) 상세: 막대(← 진행목표 · 경로 · [편집]) → 라벨 배지 + 제목(h2) → 기간 "10.01(목) – 10.07(수) · D-3 / 진행 중 / 종료" → 진척률 막대 + "과제 N개 · 제출 x/y" → 설명(MarkdownView, 비었으면 "회차 설명이 아직 없어요") → "이 회차의 과제 N개" 읽기 전용 목록(유형 배지·제목·기간·내 상태(나에게 배정된 경우 `CODE_LABEL`)·`sub/asg`), 줄 클릭 = 과제 상세(replace).
- 과제 상세: 막대(← 진행목표 · 경로 링크(회차) · [편집]) → 유형 배지 + 제목 → 기간·D-day·상태 → 설명 → 담당자별 제출 상태 카드(기존 `LeafDetail` 내용을 `LeafBody` 로 뽑아 재사용) → "plan 06: 제출" 자리 유지.
- 보관 항목: 편집 권한자는 목록에서 보관 항목을 보고(지금처럼) 상세도 열 수 있다 — "보관됨" 배지. 참가자 목록에는 지금처럼 보인다(서버가 보관 포함으로 내려줌, 흐리게) — 동작 변경 없음.
- Esc = 목록. 포커스: 열면 h2, 닫으면 열었던 행(편집 화면과 같은 `lastOpen` 로직을 공유).
- 보드 카드·캘린더 팝오버·간트 리프·알림 `?task=` → `goLeafPatch` 가 이제 `viewSel: id` 를 연다(인라인 펼침 대신). `openLeaf` 상태는 제거.
- 간트 회차/묶음 이름 클릭: 지금은 접기 → 그대로(꺾쇠가 따로 있으면 이름 = 상세로 바꾸는 것은 범위 밖).

| 보관된 회차 | 선택 목록에서 제외, 그 회차의 과제 섹션 추가 버튼 숨김(서버 `PARENT_ARCHIVED` 방지) |
| 기존 묶음 | 목록·간트에 그대로. 묶음 행 "+" 없음. 묶음 화면 과제 섹션은 추가 가능. 묶음 안 과제는 회차 선택으로 회차 바로 아래로 |
| 이동 중 권한 회수 | `NOT_CURRICULUM_EDITOR` → 기존 처리(편집 모드 닫기·재조회) |
| 상세 화면 URL 의 항목이 삭제됨 | 목록 + 주소 정리(`itemTarget` 기존) |
| 보기 모드 `?item=` 를 편집 권한 없는 사람이 열기 | 상세 화면(읽기). `mode=edit` 이 있어도 권한 없으면 상세 |
| 임시 노드(`.newN`) | URL 에 싣지 않음(기존). 상세/편집에서 링크·이동 비활성 |
| 한 회차 과제가 많음(20+) | 섹션은 내용만큼 자람, 페이지 스크롤 |

## 5. 수용 기준

1. 편집 모드에서 회차 행 "+" 를 누르면 목록에 머문 채 그 회차 끝에 입력이 열리고, 제목 입력 후 Enter 로 과제가 회차 안에 들여쓰여 나타나며 입력이 다음 과제를 위해 비워진 채 포커스를 유지한다. Esc 로 닫힌다.
2. 펼친 각 회차 끝에 "+ 과제 추가" 줄이 있고 같은 동작을 한다. 과제·묶음 행에는 "+" 가 없다.
3. 새 과제 기본값 = 공통, 회차 기간, 끝 순서, 활성 참가자 전원 배정.
4. 회차 편집 화면에 "이 회차의 과제 N개" 섹션이 있고 각 줄에서 열기·위/아래·삭제, 섹션 끝에서 추가가 된다. 회차를 저장하지 않아도 동작한다.
5. 과제 편집 화면 경로의 회차 조각을 누르면 그 회차 편집 화면이 열린다(미저장이면 확인).
6. 과제 편집 화면의 "회차" 선택으로 다른 회차로 옮기면 목록·간트·보드에서 새 회차 아래에 보이고, 기간은 3.5 규칙대로(미리보기 문구와 결과 일치), 담당자·제출은 그대로다. 미저장 수정이 있으면 선택이 비활성이다.
7. 데스크톱 목록에서 과제를 드래그해 같은 회차 안 순서를 바꾸거나 다른 회차로 옮길 수 있다(3.5 규칙 동일).
8. 보기 모드에서 회차 행 본문을 누르면 회차 상세(기간·진척률·렌더된 설명·과제 목록)가 열리고, 과제를 누르면 과제 상세(설명·유형·기간·담당자별 상태)가 열린다. 꺾쇠는 접기만 한다.
9. 상세 화면 URL 은 `?tab=curriculum&item=<id>` 이고 뒤로 가기 = 목록, 새로고침 = 같은 상세, 회차 → 과제 이동은 replace. 편집 권한자는 "편집" 으로 같은 항목의 편집 화면에 간다.
10. 보드·캘린더·간트·알림에서 과제를 열면 과제 상세가 열린다. 보드는 현재 회차 필터로 시작한다.
11. 390/820/1440 에서 가로 스크롤 없음, 안쪽 세로 스크롤러 없음, 새 버튼 누르는 자리 ≥44px.
12. 새/바뀐 문구는 "진행목표" 를 쓴다(뒤로 버튼 "← 진행목표", 트리 aria-label "진행목표").
13. 마이그레이션 없음. `npm run lint && npx tsc --noEmit && npx vitest run` 통과.
